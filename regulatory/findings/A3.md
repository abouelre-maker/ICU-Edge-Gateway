# A3 — OBX-11 result status: corrections dropped, empty status silent

**Status:** PROPOSAL — UNSIGNED, pending clinical safety review (HD-E4).

## Hazardous situation
- A corrected result (OBX-11 = `C`) was discarded, so the erroneous earlier final value remained the one used for scoring.
- An empty OBX-11 was accepted silently.
- A lowercase status was accepted without trace.

## Change (risk control, proposed)
- `C` is accepted.
  - Within a message, a corrected value replaces any earlier F/P value of the same vital sign type observed at or before it (`_apply_corrections`).
  - `CORRECTION_PENDING` (informational) tells consumers to supersede any previously sent result. Cross-message retraction is not possible without a result store (deferred, the same gap as Q4).
- An empty OBX-11 is accepted but reported (`MISSING_RESULT_STATUS`, informational).
  - Note: many existing fixtures place the status in OBX-10, leaving OBX-11 empty.
  - Rejecting such messages would drop data, and a later decision could tighten this.
- A lowercase status is normalised, with a warning.
- W, X, I, D and other statuses are still excluded.
- `VitalSignSample.result_status` carries the status to FHIR (used by N-02).

# A8 — MLLP acknowledgement correctness

**Status:** PROPOSAL — UNSIGNED, pending clinical safety review (HD-E4).
**Partially closed:** idempotency is BLOCKED-TEST-CONFLICT (A8-1); durable storage is deferred.

## Hazardous situation
- MSA-2 did not echo the sender's MSH-10, so senders could not correlate ACKs.
- AR was never sent, and AA was returned for unusable messages, so the sender believed data had been delivered.
- ACK IDs collided within one second.
- The SpO2 scale was global per listener.
- Batch envelopes were not handled.

## Change (risk control, proposed)
- MSA-2 echoes the inbound MSH-10. It is extracted by regex even when the message cannot be parsed.
- The ACK's own MSH-10 is `ACK` + 17 random hex characters (unique).
- AR is sent for an undecodable frame, an unsupported message type (not `ORU^R01`), or a batch envelope (FHS/BHS).
- AE is sent for an unparseable message or a message with no usable observation. Nothing is forwarded.
- AA means the message was accepted into the store-and-forward buffer.
- Optional `spo2_scale_resolver(patient_id)`, for a per-patient Scale 2 assignment. When absent or unknown, the documented default applies (same as HTTP `/ingest`).

## Open / residual
- **A8-1 (HD-E6):** no de-duplication by MSH-10; an existing test locks in re-processing.
- **Durability (known gap):** AA acknowledges acceptance into an **in-memory** buffer, not durable storage. A restart before forwarding loses the data. A durable queue is not in Phase 1 scope.
- No per-patient scale registry exists yet. The resolver is the integration point.

# A6 — Critical values indistinguishable from artifacts

**Status:** PROPOSAL — UNSIGNED. Decided by delegation 2026-09-29, pending review by a
clinical safety reviewer (HD-E4). Not an approved risk-control record.

## Hazardous situation
A physiologically extreme reading (e.g. HR < 20, RR < 3, SpO2 < 50, SBP < 40,
T < 28 °C) was classified as an instrument artifact. It was excluded from NEWS2,
and the response was HTTP 200 with no score and no machine-readable outcome.

A patient in cardiac or respiratory arrest and a disconnected lead looked
identical to a consumer. A consumer that reads only the numeric score saw
"no score" at the moment of greatest risk.

## Change (risk control, proposed)
- New outcome contract (`src/domain/entities/score_outcome.py`).
- New `ScoringGate` (`src/domain/services/scoring_gate.py`), run before the unchanged `NEWS2Calculator`.
- Two tiers, **no threshold value changed** (R6):
  - **Artifact** — physically impossible data only: NaN/Inf, negative values, SpO2 > 100 %, O2 flag not 0/1. The value is excluded, as before. Reason `ARTIFACT_EXCLUDED`.
  - **Critical** — any finite, physically possible value outside the existing `PhysiologicalBoundsChecker` bounds. NEWS2 is computed normally from the RCP 2017 tables. The outcome is `OUT_OF_RANGE_CRITICAL`, reason `CRITICAL_VALUE_REVIEW_REQUIRED`, and the measured value is preserved in the finding and in the FHIR `OperationOutcome` diagnostics.
- HTTP 200. Headers `X-Score-Outcome` and `X-Score-Reasons`. A valid-R4 `OperationOutcome` bundle entry carries every reason code.

## Interpretation made (needs reviewer confirmation)
- The upper side of the bounds (HR > 250, RR > 60, SBP > 300, T > 45 °C, DBP > 200) is treated the same as the lower side: **critical, scored, flagged**.
  - The delegated decision listed only the low-side values.
  - The symmetric reading was chosen because it errs toward a high score plus a review flag, never toward "no score".
- Diastolic BP is not a NEWS2 input, but an extreme DBP still raises the critical outcome.

## Residual risk
- A true lead-off that reads 0 is now scored high (HR ≤ 40 → 3) and flagged. Per the decision, false alarms are judged the lesser harm; the flag lets reviewers tell the two apart.
- The per-vital FHIR Observation for a critical value still carries `dataAbsentReason = out-of-range` (observation builder unchanged). The value is preserved in the `OperationOutcome`. To be revisited with the FHIR work (Phase 3).

## Verification
- `tests/unit/test_a6_critical_values.py` (12 tests): six extreme values scored and flagged; the critical warning is not labelled artifact; NaN / negative / SpO2 > 100 remain artifacts with no score; a normal set is still scored; the `/vitals` API returns 200 with `X-Score-Outcome: critical` and an `OperationOutcome` carrying the measured value.
- Full suite after the change: 828 passed, 1 xfailed, 0 failed; no existing test changed.

# A5 — Coding system ignored; different quantities mapped to one NEWS2 input

**Status:** PROPOSAL — UNSIGNED, pending clinical safety review (HD-E4).
**Partially closed:** two sub-items are BLOCKED-TEST-CONFLICT (A5-1, A5-2 in HD-E6).

## Hazardous situation
- LOINC `2708-6` (arterial-blood saturation, SaO2) was read as SpO2.
- Arterial pressure (`ABP-*`, `ART-*`) collided with NIBP in the same NEWS2 input.
- `SO2`, `SAO2` and `STO2` (tissue oxygenation) were read as pulse-oximetry SpO2.
- `T1` and `T2` (site-unspecified) were read as core temperature.
- The OBX-3.3 coding system was ignored.

## Change (risk control, proposed)
- Removed from the input tables: `2708-6`, `SO2`, `SAO2`, `STO2`, `ABP-S`, `ART-S`, `ABP-D`, `ART-D`.
- A code declared as LOINC (`LN`) is looked up only in the LOINC table (no fallback to proprietary codes).
- Every unmapped OBX-3 now produces an `UNRECOGNISED_CODE` finding (informational), not just a log line.

## Blocked (HD-E6)
- **A5-1:** `T1`/`T2` remain mapped to core temperature, because the demo tests lock them in.
- **A5-2:** a LOINC-shaped identifier under a non-LOINC system still falls back to the LOINC table, because the vendor edge-case tests lock it in.
- The desired behaviour for both is recorded as strict-xfail tests.

- Full suite: 916 passed, 4 xfailed (1 pre-existing + 3 new strict-xfail).
